# 分类推送与固定晚报

## 正文结构

三类消息共用统一的只读报表快照。定时早晚报采用精简但完整覆盖的排版：顶部交叉统计、紧急事项、市级和各区的重点详情／其他在途简列、待核实信息与查询入口。即时通知及既有全量导出保留原排版。

四类概览各占一个独立段落，固定显示认租中和在途，本期事件只追加非零项；全部为零时显示“本期无变化”。市级、区级和公租房保留个人／单位／待核实分布，个人和单位栏目不重复其自身分布。重点批次约四个短段：编号和短名称、状态及关键时间、对象概要和项目所在地、变化／办理提示及原文链接。其他在途每批一个短段。使用Markdown空行，避免普通换行被合并成空格。

“在途”表示尚未明确结束、仍在跟踪的配租批次，包括尚待开始认租、正在认租及等待后续核查／摇号／选房／签约公告等状态，不代表仍可申请。正文顶部已加入说明；是否可申请以认租窗口及官方要求为准。当前跟踪范围为近120天有节点的未结束批次，正在认租者不受120天限制。

- 市级/区级按原配租公告的组织机构判断，转载网站不改变归类。
- 保租房、公租房决定对应组织层级和地区下的子栏目。
- 个人、单位定向、对象待核实是每个批次的对象标签；对象仅展示有证据的类别概要，完整资格条件及例外通过官方原文查看，不推导全市通用资格。
- 顶部保留市级保租房、区级保租房、面向个人配租、面向单位定向配租四栏；层级与对象交叉，不能相加。公租房独立汇总。
- 全市总计按公告/批次去重。同一批详情只展开一次，按原配租公告编号为 B＋ID；未可靠关联的独立公告编号为 N＋ID，不计作已确认批次。
- 各区固定顺序为福田、罗湖、南山、盐田、宝安、龙岗、龙华、坪山、光明、大鹏；区内优先展示临期、本期变化，再列其他在途。

## 三种任务

| 任务 | 触发安排 | 口径 |
|---|---|---|
| Scan | 07:00起每30分钟，重复15.5小时 | 只推本次实际增量；无新事件不发 |
| Digest | 08:30 | 变化取生成前24小时，状态取生成时刻；12:00前可补偿 |
| Remind | 20:30，运行器调用 evening | 固定分类晚报：当天00:00至生成时刻的变化，加当前批次和截止事项；当天23:59前可补偿 |

提前通过独立 remind 发过截止提醒，不会占用晚报日键；没有新增也有晚报。晚报中的新截止提醒进入原去重体系，已有提醒记录不重置。测试发送不登记任何正式提醒。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli digest --dry-run
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli evening --dry-run
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli remind --dry-run
```

`--dry-run` 的 JSON 包含完整 `audit` 核对清单、分类证据、原文ID、统计时段和正文。不会建立正式发送事件或报表缓存。独立 `remind` 仍用于截止提醒，不等于晚报。

## 去重、冻结和更新口径

普通报表使用每群每日 `digest:YYYY-MM-DD`、`evening:YYYY-MM-DD`。同一时段的全市快照保存在 housing_meta，后续补发及其他总群复用第一次生成的正文，不能边重试边改变统计。

早报和晚报各一条，同批次只展示一次，所有批次和公告ID仍进入投递元数据。正在认租、未来72小时内开始、本期有公告变化、核查公示正在进行，以及近7天公布而办理期限未核实的核查／选房／签约节点详列；其他条目简列。区内先重点、再简列，各组按原住房类型和快照顺序展示。

对象概要不能将否定、并列选择或例外缩成肯定门槛，无法可靠概括时显示“对象见原文”。跨区项目所在地、可靠房源数、公示日期与户数、数据疑点保留。无新变化的过期认租窗口只保留截止日期，不再重复完整起止时间和全部等待节点。重点提供启动、当前及本期变化的原文链接；简列提供当前阶段原文，等待后续时链接至启动公告。完整原句、分类证据和流程历史保留在冻结 audit 中。

单条同时满足18000字符和18000 UTF-8字节的保守预算，测试前缀也计入。较繁忙时自动压缩字段名和区域重复统计；机构前缀可由所在区域标题提供。顶部完整分类统计、批次、日期、链接、数据疑点及成员ID不删减；仍超预算则明确失败，不截断或拆发。即时事件通知保留原分段能力。

新早晚报快照使用schema 3及布局标识 `compact_daily_v1`，另存逐批展示级别、重点原因、短名称和对象概要。已有schema 2日快照原样复用，不改写已发送正文，不重新占用当日日键。详细验证和预览见[早晚报精简排版验收](早晚报精简排版-2026-10-22.md)。

首次采集、历史补抓和重新解析时间不表示官方修改。仅对已抓取完整详情的后续业务版本变化、已知附件内容哈希变化记录修订证据；报表根据这些证据列“本期更新”。启用此版本前没有证据的历史更改不倒推成今天的更新。修订证据只保存版本哈希、时间和原因，不复制个人名单。

认租截止后显示“认租已结束，待后续公告”。缺窗口显示“认租时间待核实”，不能推断尚未开始。只按实际阶段公告推进，预告和未来/待核实日期不推进阶段。近120天有节点的在途批次加载完整历史；正在认租的批次不受120天窗口限制。公租房、单位批次没有摇号依据时不增设摇号节点。

## 手动排版验收

默认只预览；加 `--deliver` 才向启用的总群发送。即时样例使用库中最近三天内的真实候选公告，早晚报使用生成时刻的真实快照。样例明确标记为验收，不表示公告再次新增或正式任务已执行。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli report-test --kind instant
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli report-test --kind digest
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli report-test --kind evening

# 明确需要真实发送时使用：
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli report-test --kind instant --deliver
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli report-test --kind digest --deliver
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli report-test --kind evening --deliver
```

三类验收均使用独立 `test` 事件和缓存，不占正式早晚报日键，不登记截止提醒，不刷新或取消其他正式待发消息。正常早晚报 `--force` 同样使用独立测试记录，不能用它证明正式定时任务已完成。
