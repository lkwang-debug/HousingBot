# 全市摇号竞争统计与情景分析

本轮覆盖市级和全部十个区级区域，沿用现有来源。光明用于完整对照，统计逻辑不按地区限定。每批保留官方面积／户型、队列名称和顺序；不把一房转换为50㎡，不复制光明的多孩优先或分轮审核规则。

## 当前核对结果

- 盘点14个独立摇号事件，18份公告及镜像均有可校验的本地名单。市级、福田、宝安、龙岗、龙华、坪山、光明有已采集记录；其他区域列明“当前已采集数据中无摇号公告”，不表示当地没有房源。
- 12个档位可计算申请竞争比。其余明确列出批次未关联、同档房源未对应、多轮排序歧义、队列未公开或规则未复核等缺项。
- 光明当前四档：3746／111＝33.7，1526／76＝20.1，1848／549＝3.4，3810／1227＝3.1户申请一套。
- 宝安2026年度个人批次：一房15384户／167套＝92.1，两房8290户／259套＝32.0，三房1646户／37套＝44.5。一房含7套有特殊优先条件的无障碍住房，整体竞争比不是普通家庭个人机会。依据[官方配租公告](https://www.baoan.gov.cn/bajshej/gkmlpt/content/12/12930/post_12930935.html)。
- 坪山两组未关联启动公告的转载，按同区域、同标题、同日期及相同官方附件身份合并；合法不同日期／附件／轮次保留。

## 数据与规则边界

`lottery-evidence:<公告ID>`只保存匿名家庭数、记录条数、队列数和原名单轮次统计，不保存姓名、证件号或逐户资格备注。证据绑定公告业务版本、附件版本、批次关联及附件清单；版本变化后不沿用旧统计。

报表、查询页使用同一个竞争统计结果：同档完整家庭数÷可靠初始配租套数，四舍五入保留一位小数。镜像不累加，跨轮或重叠房源池不强行合并。未公开队列不影响已经独立核实的总家庭数，但不能生成虚构队内排名。初始套数不是实时剩余。

已关联核查公告的合格／不合格家庭数，标明该公告范围单列，不把未审核家庭算成不合格。项目意向、特殊优先分组未公开时，不从编号或姓名推断，也不沿用文章估算。

已核实的光明、宝安条件摘要各自按原公告展示。其他批次有完整短条款时保留条款，否则说明待复核并链接本批来源。条件摘要核对不等于具备个性演算所需的完整规则和排序。

规则引擎版本为`opportunity-v3`。已复核规则可以声明本批`queue_order`和`special_priority_conditions`，优先条件以家庭人数／未成年子女人数的具名条件组合表达。光明旧版`gm-2026-038-v2`保留兼容适配；其他规则不继承光明条件。资料不齐全的批次仍可查询已核实事实，不能宣称已启用完整预测。

## 情景分析

编号和本人队列先查询，分析区继续由本人确认已申报项目及家庭情况。先显示直接结论，再默认收起“如果前面有些家庭没有选这些房源呢？”

固定对比前面每100户最终有100／80／60户占用所选房源。占用数向上取整，不重复叠加审核、放弃、项目分流。无同档其他项目时不提示项目分流。三档均为假设，不是历史实测或个人成功概率。

未知优先重排影响当前排序时，主结论提示等待核查和正式排序，不能只因普通参考顺序在容量内就宣称能上车。已核实正式排序范围后优先采用正式排序，不重复叠加家庭优先。
