# HousingBot v2 运行说明

> 分类排版已升级：08:30为分类早报，20:30为每日固定分类晚报；独立截止提醒另由 remind 命令提供。最新排版、统计和验收规则见 [分类推送与固定晚报](分类推送与固定晚报.md)。下文旧“20:30仅提醒”的描述以新说明为准。

适用环境：Python 3.10、SQLite、Windows 计划任务。电脑需要开机且用户保持登录，锁屏可以，注销后不承诺继续运行。

## 多个全市群

实际配置在 `data/groups.json`。保留已有群的 `id`；修改显示名不会重复推送。新增群使用新的稳定 ID、独立 topic，`tier` 为 `pro`，`regions` 为空数组。

```json
{
  "groups": [
    {"id":"shenzhen-001","name":"深圳一群","label":"深圳住房管家","topic":"填写实际群编码","enabled":true,"tier":"pro","regions":[]},
    {"id":"shenzhen-002","name":"深圳二群","label":"深圳住房管家","topic":"另一个实际群编码","enabled":true,"tier":"pro","regions":[]}
  ]
}
```

示例不要覆盖现有群 ID。重复 ID、重复非空 topic 会报错，避免重复发送。同一人加入多个群会收到各群广播；没有用户级去重。新群从首次启用开始接收即时消息，不补历史，早报仍包含存量。暂停使用 `enabled:false`；恢复后不补暂停期间的即时消息。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli groups
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli doctor
```

## 待发消息与人工核对

每个群独立记录消息包和事件，正文在入队时冻结。只补失败群，不会将新公告混入原失败包。缺少 token 或 topic 为 blocked，配置恢复后可继续投递。接口受理为 submitted，不代表微信最终送达。

临时错误最多自动尝试三次，间隔 5、30 分钟，由后续任务轮次领取，因此实际间隔可能更长。超时、响应不明或发送进程中断进入 needs_review，需人工核对，不自动重发。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli outbox --status needs_review
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli outbox-resolve 123 received --note "已核对群内收到"
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli outbox-resolve 123 retry --note "确认群内未收到，补发原包"
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli outbox-resolve 123 cancel --note "无需再发"
```

`legacy-unmapped` 为无法从旧记录确定目标群的历史消息，不会自动发送，也不影响当前群新消息。先核对历史记录再映射：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli outbox-resolve 123 map --group-id 当前实际群ID --note "已核对历史目标"
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli outbox-resolve 123 received --note "旧接口记录受理，归档"
```

旧记录没有保存原始正文，禁止直接 retry。发送端使用操作系统锁和跨进程限速，异常退出后锁自动释放；任何客户端都无法仅靠本地记录保证网络发送严格一次，因此不明状态必须人工处理。

## 批次和预测

批次锚定原配租公告，个人和企业不能相互借用房源。引用文号明确或唯一候选满足规则才自动关联。歧义记录可在 `show` 和 `doctor` 查看，核对官方文号后手动指定：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli batch-link 摇号公告ID 配租启动公告ID
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli predict --notice-id 公告ID --queue 第一队列 --order 500 --category 40
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli predict --notice-id 公告ID --queue 第一队列 --rank 50 --category 40
```

`--order` 需要在真实名单里核实，`--rank` 明确表示假设队内排位。无法核实批次、房源或名单时暂停估算。供需比例不是个人成功概率。资格提示引用原句，不对具体家庭资格下结论。

## 查询页：自动生成，人工上传

新名单或分档房源变化后，扫描完成时自动构建受影响页面；构建失败保留上一版。清单在 `lookup/manifest.json`，包含页面哈希、批次版本、条数和异常。`lookup.zip` 是历史导出包，不会自动刷新，上传时请使用当前 `lookup/` 文件。

手动重建全部页面：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.build_lottery_lookup --all-districts --days 900
```

上传 `lookup/` 的 HTML 和 manifest 到现有静态托管目录，并在微信中核对入口、区域页、当天日期链接及一个已知编号。然后将清单中的完整 version 登记为已发布：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli lookup-publish --version 清单里的完整版本号
```

该命令记录人工上传确认，不调用 CloudBase，也不会自行证明线上文件正确。未登记或源版本已变化的批次，不在推送中宣称已可查。日期参数只是前端使用门槛，不是会员鉴权；页面下发编号、队列、顺序号、排位和轮次，不下发姓名和证件号。

## 数据迁移与回滚

先停用 HousingBot 三个任务并等待正在执行的实例退出。迁移只处理 housing 表和新的 housing_meta 版本，不修改旧股票表或 alembic_version。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli migrate
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli migrate --apply
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli repair-data --baseline
```

第一条在临时副本演练；第二条先备份再迁移；第三条重新读取摇号和相关房源，修复关联与页面，不生成历史即时通知。迁移可重复执行。不能将修复回填当作需要给所有群补发的新增公告。

回滚前停止全部任务及进程，恢复备份的整套代码、配置、数据库和查询页面，再重新注册任务。不要在 SQLite 仍有连接时直接覆盖数据库；备份使用 SQLite backup 接口，恢复时需确保不混用旧的 WAL/SHM 文件。

## 日志、备份和验收

- `logs/housing-YYYY-MM-DD.jsonl`：结构化业务日志及异常。
- `logs/task-模式-YYYY-MM-DD.log`：任务标准输出、错误输出、开始结束时间和退出码。
- `data/backups/housing-*.db`：每日首次扫描前备份，保留 14 天。
- 返回码 0 表示本次处理正常，2 表示来源、投递或页面构建存在降级，1 表示未处理执行异常；服务商受理与任务进程结果分别检查。
- 早报可在 12:00 前由扫描任务补偿，每群每天只建立一份普通早报；过期的旧早报与已失效截止提醒不会跨天补发。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli digest --dry-run
.\.venv\Scripts\python.exe -X utf8 -m app.housing.cli remind --dry-run
```

恢复任务后至少观察一个完整日周期，核对扫描、08:30 早报、20:30 提醒以及各群实际收件。自动回归使用模拟发送，不联系真实群。
